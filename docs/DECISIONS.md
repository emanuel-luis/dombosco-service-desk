# Decisions

Decisions taken while turning the college project into a maintained portfolio repo. Newest last.

| # | Date | Decision | Choice | Why |
| --- | --- | --- | --- | --- |
| 1 | 2026-10-27 | Visibility and identity | Public portfolio repo; keep the school name, the domain and the college team origin; credit the team in the README | It is a real team project and reads best with its context intact |
| 2 | 2026-10-28 | Repository name | `programacao_web` renamed to `dombosco-service-desk` (an interim `dombosco-atendimento` name was dropped) | An English name that says what the app is; the Django project package follows when the settings are rewritten, if the rename stays cheap |
| 3 | 2026-10-28 | Secret scan before going public | gitleaks over every ref plus a manual sweep of every blob: no live secret, no real people's data. Dev-only values that sat in history (the Django `django-insecure-` startproject key, the local compose Postgres password, test-script passwords) are treated as burned and never reused | A public history cannot be unpublished |
| 4 | 2026-10-28 | Unmerged teammate branches (`felipe`, `Tarcisio/alteracoes`) | Bring in the useful fixes with `Co-authored-by` credit (PR #3) instead of merging the branches as they are; keep both branches | The `felipe` super-user screen keyed on the wrong group and sent edits to an endpoint that ignores them; the `Tarcisio/alteracoes` redirect sent signed-in users home on every reload |
| 5 | 2026-10-28 | Commit identities | History rewritten once so the owner's commits use his personal address (author and committer); two older personal addresses in a test script were replaced too; teammates' identities untouched | Personal portfolio identity; pull-request refs that keep the old commits go to GitHub Support |
| 6 | 2026-10-28 | Old branch protection on `main` | Removed for the one rewrite push; the portfolio protection (required CI checks, no force-push or deletion) is applied once the repo is public | A force-push is impossible under the old rule; until then changes reach `main` only through PRs with green CI and review |
| 7 | 2026-10-28 | Visual identity source and palette | Use the official Dom Bosco logo and the palette of www.dbosco.com.br (purple `#6c4b92` primary, magenta `#bf3488` call to action, yellow `#fce92e` highlight only), with the owner's approval; text colors checked against WCAG AA and adjusted only where they failed (muted grey, error red). Details in `docs/BRAND.md` | The project is a school service desk and should look like the school it was built for; the main site wins over the campaign subsite because it is the canonical identity |
| 8 | 2026-10-28 | Typography | Montserrat (headings) and Nunito Sans (body) through `next/font/google`, replacing the site's Museo and Trueno | Museo and Trueno are not openly licensed and cannot be bundled in a public repo; the build downloads the open fonts, so there is no runtime request to Google |
| 9 | 2026-10-28 | Unofficial-project notice | A pt-BR notice in the footer of every screen, next to the login form and in every email (signup templates plus the allauth base template) (README to follow); emails are signed "Equipe Dom Bosco Service Desk (projeto acadêmico)" instead of the institution | The repo uses the school's name and mark but has no affiliation or endorsement; every surface must say so and must not speak as the institution |
| 10 | 2026-10-28 | Event log design | Append-only `request_events` table, one immutable row per lifecycle event (who, role, UTC time, from/to status), written in the same transaction as the change; enforced by a model guard and a Postgres trigger; idempotent backfill for older requests | Analytics need history that the OLTP rows overwrite; a trigger protects the log even from code that bypasses the model |
| 11 | 2026-10-28 | Analytics metric semantics | First response is the first staff answer or the first staff or admin comment. Closed only when the current status is terminal. Throughput counts events (reopenings and deleted requests included); backlog and SLA exclude deleted requests. SQL views and pure-Python definitions must stay equal, checked by a reconciliation test | Event counts are exact and cheap to explain; one definition in two languages keeps the export portable and the views testable |
| 12 | 2026-10-28 | Parquet export | `export_analytics` writes request_events, request_lifecycle and daily_throughput with pyarrow contracts and a `_run.json`; `make export` writes inside the container and copies the result out instead of bind-mounting | Contracts fail before anything is written; a bind mount would create root-owned files on the host |
| 13 | 2026-10-28 | Frontend upgrade | Next 16 and React 19 (Node 24, ESLint 9) | Next 14.2 had critical security advisories |
| 14 | 2026-10-28 | User model | Email-only users: the `username` column was dropped (migration 0003) | The app signs in by email only; the column was unused |
| 15 | 2026-10-28 | DEBUG permission bypass | Removed; permissions no longer depend on `DEBUG` | A debug flag must never change who may do what |
| 16 | 2026-10-28 | Django package name | Project package renamed from the old name to `dombosco_service_desk` | Matches the repository name |
| 17 | 2026-10-28 | Known gaps | Google sign-up at the staff domain does not grant staff (only a confirmed email does); deleting a user in the Django admin cascades their comments without `comment_deleted` events; JWT stays in localStorage without a refresh flow. All three are listed in the README | Each needs a design change beyond the refactor; documenting beats hiding |
| 18 | 2026-10-28 | License | MIT, copyright held by the three authors (Emanuel Luis, Felipe (felipeoak1) and Tarcísio (tarcisio)) | The code was co-written by the team; the owner chose MIT with the three authors named |
| 19 | 2026-10-28 | Diagrams | D2 sources in `docs/diagrams/` rendered to committed SVGs with D2 0.9.0 (pinned with its checksum in the Makefile, ELK layout, light and dark themes), checked by the `diagrams` CI job | Readable architecture, data-flow, user-flow and data-model diagrams that cannot drift from their sources |
